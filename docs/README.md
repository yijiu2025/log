## 1. `AUDIT-PROMPT.md` —— 审查提示词模板

**用途**：把「角色」到「输出格式」整段作为提示词交给具备文件读写能力的 AI 代理，
对 `packages/log` 做一次深度代码审查。

**特性**：
- 无日期、无版本基线 —— 提示词内的路径 / API / 约定**对应当前真实代码**，可直接使用。
- 内含「先读懂设计约束（这些是有意为之，不要当 bug 报）」章节，可有效抑制
  「把既定设计当缺陷重复上报」这类噪声。当前收录 **10 条编号约束**（文件输出默认关闭、
  `createLogger` 仅两参、全局 `log` 是 Proxy 门面、通道独立级别、零运行时依赖、
  日志调用自身永不抛异常等）。
- 每次代码演进后，若 API 或设计约束发生变化，**应同步更新本提示词**，
  否则下一轮审查会产生虚假问题。

**使用方式**：新一轮审查 → 复制本文件正文 → 交给 AI 代理 → 产出新的 `AUDIT-REPORT-*.md`。
新报告应带**当轮**的日期与基线版本，并在「修复记录 / 交付状态」段标明闭合情况。

## 2. `AUDIT-REPORT-comments.md` —— 注释审查报告

**审查范围**：仅限 JSDoc 与文件头注释的正确性、完整性与一致性。
**方法**：逐文件通读 11 个源码文件的注释，与实现逐条对照。

**评级**：`6.5/10` —— 扣分全部来自「注释与实现不符」与「缺失」，与代码逻辑无关。

**问题清单**：P1 6 项 / P2 9 项 / P3 4 项（P1、P2 在正文逐条展开，P3 仅在摘要中列数、
未逐条展开）。

**核心价值**（为什么不该删）：
- 报告的第 5、6 节记录了**每一处修复的文件:行**（P1-1 ~ P1-6、P2-1 ~ P2-9 共 15 项 + 附带 1 项），
  第 6 节末尾还有「新增回归测试」与「验证结果」。
- 报告指出的核心风险是**「文档说了旧行为，使用者照着写会踩坑」**：
  0.4.0 / 0.4.1 两轮 API 变更（`createLogger` 从多参变两参、`LOG_FILE` 默认值翻转）
  未同步到注释。这类问题最难排查，修复依据值得留存。
- 典型的 P1：`index.js` 文件头还在用 `createLogger('pay', { level, file })` 这种
  已废弃写法 —— 照抄会得到一个对象被当成 `asGlobal` 布尔值、配置被**静默丢弃**且无报错。

## 3. `AUDIT-REPORT-fullstack-rules.md` —— 规范审查报告

**审查依据**：`.claude/skills/fullstack-rules` v2.5.0（企业级审查清单 + 反模式库）。
**审查对象**：`packages/log/src/*`（2586 行）及其适配层 `src/framework/log/*`、调用方若干。

**评级**：🔴 严重 0 / 🟡 中等 5 / 🔵 低 7。

**核心发现**：无严重问题；安全防线（`safeSeg` + `isInside` 双重校验、脱敏、frozen 配置）实测有效。
主要问题集中在 **「配置写错时静默失效」** —— 报告的原话是：

> 这是本库作为「可观测性基础设施」最反讽的一类缺陷：日志库自己出问题时不吭声，
> 使用者以为日志记上了，实际一条没有。

**闭合情况**：F-1 ~ F-12 **12/12 全部修复**，落在提交 `2aad119`
（*防静默失败——降级告警出口 + fatal 兜底 + 非法配置留痕*）。

**核心价值**（为什么不该删）：
- 报告末尾的「设计取舍说明」记录了三处**关键决策及其理由**，这是代码本身看不出来的：
  1. `parseLevelOpt` **保持纯函数** —— 告警逻辑抽到新增的 `validateLevelOpt` 包装层，
     职责分离（现有测试与推导逻辑依赖其「纯」这一性质）。
  2. **文件通道失败仍不向上抛** —— 日志库铁律（绝不污染业务），修复只补「留痕」不改变控制流。
  3. **告警必须限流** —— 磁盘满 / 权限错会持续触发，按错误码去重，每类故障每进程只提示一次。
- 还含「真实包回归明细」（从 npm 装 0.5.0 后跑 9 项行为验证，非 workspace 软链）与一份踩坑记录。

## 维护约定

- 新增审查报告时，在本文档表格中补一行，并写明**当轮日期 + 基线版本 + 闭合状态**。
- 报告一旦闭合，**保留原文，不要删问题清单** —— 那份清单是修复的验收标准。
- 若当前版本与某报告基线的差距已经大到「报告结论不再适用」，
  正确做法是**新写一份报告**，而不是改写旧报告（旧报告的价值恰在于「当时是什么样」）。
